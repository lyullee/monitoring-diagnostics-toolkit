## 필터

[HSE 공개 필터 자료, 배포 v8](https://www.kaggle.com/datasets/prognosticshse/preventive-to-predicitve-maintenance)
의 차압(Pa), 시간(s), 공급자가 보정한 유량을 사용했다. 절대 유량 단위가 원문에서
확정되지 않아 임의로 m³/s로 지정하지 않았다. 학습 유량 중앙값 58.88099208로 나눈
무차원 비를 입력하는 `flow_input="ratio"`를 추가했다. 기준 유량과 관측 유량이 같은
원 단위를 가지면 단위가 소거된다. 기존 체적유량 인터페이스도 유지한다.

기존 q² 보정과 비음수 a·q+b·q² 혼합 저항을 비교했다. 정상 기준 후보는 시험
10~20초이며 독립적으로 정상 인증된 구간은 아니다. 별도 보정 시험의 점수 99백분위수
(하한 1)를 경보 한계로 고정했다. 지속시간은 1초다. 혼합 모형에서 a=0,
b=9.27317374 Pa로 학습되어 두 설정의 분류 결과가 같다.

공급자의 RUL은 차압 600 Pa 교체 기준까지 남은 시간이다. 원본 Test가 우측 검열되어
현재 막힘 시작의 독립 정답은 없다. `RUL≤30초`만 별도 위험 목표로 정의했으며,
RUL은 입력·학습·보정에 사용하지 않았다. 각 시험에서 Time+RUL의 일관성도 검사했다.

두 설정 모두 TP=3,426, FN=729, FP=11,228, TN=19,090이다. 이 FP는
RUL>30초에서 울린 위험 경보이며, 실제 정상 필터에서의 막힘 오경보라고 단정할 수 없다.
현재 설정은 30초 위험 경보 용도로도 오경보가 높다. 다음 개발은 시험 단위의 새 분할로
목표 시간을 먼저 정하고 수명·변화율 모형을 비교해야 한다. 이번 평가 자료로 재보정하면
별도 개발 결과로 표시하고 새로운 최종 평가 자료를 확보해야 한다.

## RO

[NREL/MHKDR 동적 RO 실험](https://mhkdr.openei.org/submissions/649)의 실제
공급·농축 압력(psi), 투과수 유량(L/min), 온도(°C), 전도도와 SW30-4040 막면적
7.4m²를 연결했다. 전도도→염 농도는 배포 README의 0.6638 계수와 원 단위를 사용했다.
투과수 전도도는 µS/cm이므로 mS/cm으로 환산한다. 삼투압은 완전 해리 이상 NaCl 근사다.
농도 분극·활동도는 모델링하지 않았다. 온도 정규화는
[DuPont FilmTec 기술 매뉴얼](https://www.dupont.com/content/dam/water/amer/us/en/water/public/documents/en/RO-NF-FilmTec-Manual-45-D01504-en.pdf)
식 73/74의 경험식 역수를 사용했다(원식의 273/298 상수 유지).

**엄격한 검사에서 학습 자료 전체가 농축측 압력 > 공급측 압력으로 나타났다.**
따라서 평균 공급·농축 압력에 기반한 정상 투수성 기준은 학습할 수 없다.
열 교환·센서 오프셋의 이유는 배포 자료만으로 확정하지 못했다. 열 이름을 바꾸거나
압력을 임의 보정하지 않았다. 공급자 센서 위치·교정·압력 기준 확인이 우선이다.

계산 연결을 확인하기 위해 별도로 공급압만 막 측 압력으로 사용하는 **미검증 근사**를
실행했다. 막 용기 압력 손실 0, 투과측 게이지 압력 0이라는 확인되지 않은 가정을
명시했다. 원래 엄격한 모델의 성능으로 취급하지 않는다. 보정 전은 수력압과 온도계수 1,
보정 후는 이상 NaCl 삼투압 차감과 FilmTec 온도계수를 썼다. 두 설정 모두 5초 지속,
별도 정상 보정 자료의 점수 99백분위수로 한계를 고정했다.

판단 행은 194,226→143,976으로 줄었다. 전체 유효 투수성의 상대 표준편차도
0.257→5.648로 커졌다. 이 통계는 운전조건이 다른 평가 자료의 단순 분산이며 고장
정확도가 아니다. 두 설정 모두 관측 경보 비율은 0%다. **오염·막 손상 정답이 없으므로
정확도·검출률·오경보율은 계산하지 않았다.** 동적 압력 명령을 이상 정답으로 삼지 않았다.

## 히트펌프

[TRI-HP 프로판 실험 원본](https://zenodo.org/records/5155136)은 실제 R290 난방
프로토타입에서 고장을 모사한 자료다. NF10/NF12의 명목 부하는 각각 10,200/12,300W다.
기존 냉동기 모형에 없는 물측 센서를 만들어 넣지 않고 `heat_pump_performance`를 추가했다.

주 로거의 응축 열량, 압축기 전력, 증발·응축 온도, 액관·토출 온도,
냉매 질량유량, 압축기 속도와 명목 부하를 사용한다. 압축기 전력만으로 계산한 난방 COP와
등온 Carnot 난방 COP의 비, 과냉도, 토출 과열도, 회전당 냉매 질량의 네 잔차를 감시한다.
이는 논문 알고리즘 재현이나 전체 보조동력 포함 COP가 아니다.

같은 네 지표에 대해 고정 기준과 명목 부하 선형 보정 기준을 비교했다. ridge=0.001,
잔차 스케일 하한은 로그 0.02/온도 0.2K이며 정상 보정 자료의 점수 99백분위수를
사용한다. 시험 고장 코드·강도와 공급자 COP는 특징에 넣지 않았다. 코드 변경은 알려진
실험 경계를 구분할 때만 쓴다. 5초 간격의 별도 흡입 과열도 로거는 10초 주 로거와
행 번호로 합치지 않았고 이번 특징에서 제외했다. 원본 시간은 ns로 명시 변환해
pandas의 µs 날짜 저장 단위에 따른 시간 축 왜곡을 막았다.

| 실험 고장 | 고정 기준 검출률 | 부하 보정 검출률 | 해석 |
|---|---:|---:|---|
| EF: 증발기 물 유량 감소 | 0.00% | 6.71% | 대부분 미검출. 실제 오염 성장 정답과도 다름 |
| CVL: 토출–흡입 바이패스로 밸브 누설 모사 | 78.87% | 79.22% | 일부 개선, 누락 잔존 |
| LL: 액관 제한 | 97.97% | 97.97% | 이번 실험 표본에서 높은 검출 |
| OC: 냉매 과충전 | 98.16% | 98.16% | 이번 실험 표본에서 높은 검출 |

고정 기준 TP/FN/FP/TN=2,457/2,828/0/490,
부하 보정은 2,635/2,650/0/490이다. 정확도 +3.08%p, 검출률 +3.37%p다.
정상 490표본의 오경보 0건은 긴 현장 운전에서의 오경보 보장이 아니다.
고장 평가 5,285표본으로 클래스가 불균형하므로 정확도만으로 평가하면 안 된다.
균형 정확도는 73.25→74.93%다. 알려진 시동 180초를 제외한 정상상태 감시 결과로,
독립적인 고장 시작 시점 탐지 성능은 검증하지 않았다.

## 구현·재현·검증 산출물

- `scripts/measured_validation_data.py`: 원본별 단위·시간·분할·정답 분리.
- `scripts/validate_acquired_modules.py`: 순차 학습·보정·고정·평가와 행별 점수 저장.
- `scripts/audit_acquired_modules.py`: 원본 정답 대조, 분할 중복·해시 검사, CSV에서 혼동행렬 독립 재집계.
- `scripts/render_acquired_modules.py`: 결과 JSON으로 비교 HTML 생성.
- `tests/test_measured_adapters.py`: 새 모듈·비율 유량·단위·날짜·보정·직렬화·극단값 검사 12개.
- 전체 기존 기능 포함 222개 시험, 별도 외부 저장소 연동시험 7개 통과.

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[public-data,physics]"
.\.venv\Scripts\python.exe scripts/validate_acquired_modules.py
.\.venv\Scripts\python.exe scripts/audit_acquired_modules.py
.\.venv\Scripts\python.exe scripts/render_acquired_modules.py
.\.venv\Scripts\python.exe -m pytest -m "not integration" --junitxml=outputs/acquired_modules_validation/regression.xml -o junit_family=legacy
.\.venv\Scripts\python.exe scripts/verify_integrations.py
```

출력은 `outputs/acquired_modules_validation/`의 `report.html`, `results.json`,
`protocol.json`, `*_frozen.json`, `*_predictions.csv`, `independent_audit.json`이다.
원시 자료·행별 예측 CSV는 배포 소스/휠에 포함하지 않는다.
저장한 최종 평가 결과는 재사용 이력이 생긴 평가 자료이므로 후속 개선의 새로운
최종 성능 주장에는 추가 홀드아웃이 필요하다.

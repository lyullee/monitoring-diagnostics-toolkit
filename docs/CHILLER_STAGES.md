# 냉동기 단계별 구현·검증 — v0.6.0

요청한 순서대로 ① 오일·과냉·과열 잔차, ② 채널별 EWMA, ③ 응축기 지표를 누적 구현했습니다.
**현재 자료에서는 추가 단계의 오경보가 커서 실사용 기본 설정으로 권장하지 않습니다.**
기존 `reference_mode="conditioned", diagnostic_stage=0`을 유지할 수 있습니다.
기존 상수 기준 모드와 API 기본값은 유지했습니다. 아래 기준 모델은 상수 기준이 아니라 v0.5 운전조건 모델입니다.

## 구현과 센서

| 단계 | 추가 입력 역할 / SI 단위 | 계산과 진단 내용 |
|---|---|---|
| 0 | 냉수 입출구·냉각수 입출구·증발/응축 포화온도 K, 냉수 kg/s, 전력 W | 냉각부하·냉수 출구·냉각수 입구 조건별 정상 전력·접근온도·유량 잔차 |
| 1 | `oil_sump_temperature`, `oil_feed_temperature` K; `oil_feed_pressure`, `oil_net_pressure` Pa; `subcooling`, `suction_superheat`, `discharge_superheat` K | 정상 부하·온도 조건으로 7개 채널을 각각 회귀하고 표준화 잔차를 기존 4채널과 결합 |
| 2 | 단계 1과 동일 | 절댓값을 취하기 전 **부호 있는 잔차** 각각에 연속시간 EWMA. 시간상수 60초, 구간마다 180초 준비 |
| 3 | `cooling_flow` kg/s 추가 | 냉각수 열량, 겉보기 UA, 유용도, 열수지 비율을 계산하고 정상 예측 대비 잔차를 추가; 냉각수 유량도 정상 예측조건에 반영 |

단계 1의 공급 압력은 **절대압**, 오일 순차압은 **차압**입니다. 모두 Pa이지만 기준이 다릅니다.
과냉도·과열도는 온도차 K입니다. 원본 °F 온도차는 ×5/9만 적용합니다. 절대온도 변환처럼 273.15를 더하지 않습니다.
원본 `PO_feed` psig에는 대기압을 더하고 `PO_net` psi 차압에는 더하지 않습니다.
과냉·과열 채널은 가공된 계측값이며 독립 센서 3개로 해석하지 않습니다.

단계 1의 추가 회귀 잔차 바닥값은 온도 0.2 K, 압력 1 psi에 해당하는 6894.757293168 Pa입니다.
기존 전력·유량 로그 잔차 바닥은 log(1.02), 접근온도는 0.2 K입니다.
단계 3은 로그 UA·로그 열수지 비율에 log(1.02), 유용도에 0.01을 사용합니다.
차수 1, ridge 0.001, 이 바닥값과 EWMA 설정을 평가 전에 고정했습니다. 별도의 최적값 탐색을 하지 않았습니다.

단계 3의 식은 다음과 같습니다. `Tc`는 측정 압력에서 변환한 냉매 포화온도입니다.

```text
Qc = mcw × cp × (Tco − Tci)
d1 = Tc − Tco; d2 = Tc − Tci
LMTD = (d2 − d1) / ln(d2 / d1)       # d1=d2일 때 연속 극한 d1
UA_apparent = Qc / LMTD
effectiveness = (Tco − Tci) / (Tc − Tci)
energy_ratio = Qc / (Qe + electric_power)
```

냉각수 유량과 양단 온도차가 양수이고 `0 < effectiveness < 1`인 경우에만 적용합니다.
UA는 등온 응축 근사에 따른 **겉보기 지표**입니다. 과열증기 냉각, 과냉, 비응축가스와 열손실을 완전히 해석한 응축기 모델이 아닙니다.
정상 회귀조건은 단계 0~2에서 `[Qe, 냉수 출구, 냉각수 입구]`, 응축기 추가 회귀에서 여기에 `log(냉각수 유량)`을 더합니다.
UA 손실은 음의 방향, 전력은 초과 방향, 나머지는 양방향으로 감시합니다. 채널 점수의 최댓값을 정상 보정 임계값으로 나눕니다.
채널별 편차는 제공하지만 고장 원인을 확정하거나 종류를 분류하지 않습니다.

EWMA는 `alpha = 1 − exp(−Δt / 60)`으로 계산하고 구간 시작 상태를 정상 평균 0으로 둡니다.
첫 점은 상태 초기화에 쓰고, 준비 구간 이후부터 판단합니다. 결측·물리범위 이탈·학습조건 이탈·시간 단절·모드/에피소드 변경 시 초기화합니다.
점수가 1을 넘는 상태가 유효 표본에서 30초 지속되어야 경보를 냅니다.
`StreamingDiagnostic`은 단계 2~3에서 정확한 배치 일치를 위해 전체 이력을 재생합니다.
기본 10,000표본 한도를 넘기면 명시적으로 거부합니다. 장기 무제한 온라인 처리에는 별도 EWMA 상태 저장 구현이 필요합니다.

## 데이터 분리와 평가 방법

- 자료: [Figshare의 RP-1043 공개 재배포본](https://doi.org/10.6084/m9.figshare.28435232), 실험 냉동기 1대. 현장 실증이나 시뮬레이션 자료가 아닙니다.
- 학습: `normal.xls`만 사용. 보정: `normal1.xls`만 사용. 평가: 기존 정상 12파일·고장 23파일 유지.
- 이전 정상 학습 구간 교차검증으로 고른 차수 1, ridge 0.001을 그대로 사용했습니다.
- 모든 단계에서 별도 정상 보정 점수의 99백분위수(최소 1)를 임계값으로 사용했습니다. 각 단계는 채널 수와 평활화가 달라 같은 숫자의 임계값을 공유하지 않습니다.
- 학습·보정 모델과 파일 목록·소스/자료 해시를 `frozen_development.json`에 저장한 다음 평가 파일을 읽었습니다. 평가 중 재학습·재보정하지 않았습니다.
- 운전 안정성 기준은 기존과 같은 과거 300초 물 온도 범위 ≤1 K 등입니다. 전체 181,700행 중 대상은 125,043행이며 전 단계에서 동일합니다. 중복 시각 제거 규칙도 동일합니다.
- 과거 평가 자료를 재사용한 개발 비교입니다. **새로운 블라인드 시험이 아닙니다.** 다른 설비나 보지 않은 날짜의 성능은 검증하지 않았습니다.

임계값은 단계 순서대로 5.98505, 18.65286, 5.33673, 5.39460입니다.
정상 보정에서의 99백분위수가 다른 정상 운전에서도 1% 오경보를 보장하지는 않습니다.

단계 1의 높은 전역 최댓값 임계값은 기존 채널의 검출도 낮출 수 있습니다. 여러 채널을 추가한다고 단조롭게 성능이 좋아지는 구조가 아닙니다.

따라서 이번 설정은 **구현 완료, 성능 채택 보류**입니다. 시험 결과로 같은 평가 자료에 맞춰 바닥값·임계값·시간상수를 바꾸지 않았습니다.
향후 정상 운전정책을 설명할 독립 자료로 모드별 정상 모델과 채널별 보정/결합 방식을 개발하고, 새로운 평가 자료에서 확인해야 합니다.

## 사용

```python
from equipment_diagnostics import ChillerPerformanceDiagnostic

# train_normal, calibration_normal, evaluation은 서로 분리한 SI SensorBatch
channels = {
    'chilled_in': 'tei', 'chilled_out': 'teo',
    'cooling_in': 'tci', 'cooling_out': 'tco',
    'evaporating_temperature': 'evap', 'condensing_temperature': 'cond',
    'chilled_flow': 'flow', 'electric_power': 'power',
    'oil_sump_temperature': 'oil_sump', 'oil_feed_temperature': 'oil_feed',
    'oil_feed_pressure': 'oil_feed_p', 'oil_net_pressure': 'oil_net_p',
    'subcooling': 'subcool', 'suction_superheat': 'suction_sh',
    'discharge_superheat': 'discharge_sh', 'cooling_flow': 'cw_flow',
}
model = ChillerPerformanceDiagnostic(
    channels, reference_mode='conditioned', diagnostic_stage=3,
    regression_degree=1, ridge_alpha=.001, persistence_s=30,
    ewma_tau_s=60, ewma_warmup_s=180,
)
model.fit(train_normal).calibrate(calibration_normal, quantile=.99)
result = model.score(evaluation)  # 모델·정상 임계값 변경 없음
# result.metrics의 channel_*_score는 정상 보정 전 채널 점수
# result.scores는 정상 보정 임계값으로 나눈 최종 점수
```

단계는 `diagnostic_stage=0/1/2/3`으로 선택합니다. 기준 JSON에는 단계·시간상수·센서 매핑·설비 식별정보가 포함되어 다른 설정으로 잘못 재사용하면 거부합니다.
동일 학습 파일을 보정에 다시 넣으면 지문으로 거부하지만, 임의로 잘라낸 중복 자료의 독립성까지 자동 증명하지는 않습니다. 파일 분리는 검증 스크립트에서 별도로 확인합니다.

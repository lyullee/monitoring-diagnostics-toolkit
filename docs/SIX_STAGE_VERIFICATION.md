## 손계산 문제의 답

각 문제는 30표본으로 만들었고 창·정상상태 확인을 통과한 **모든 유효 표본**을 비교했습니다.
정상 기준이 필요한 모듈은 먼저 기준을 학습하고, 기준 JSON 연결은 다음 단계에서 따로 확인합니다.

| 모듈 | 입력·손계산 | 예상 답 |
|---|---|---|
| 탱크 | M=100+0.3t kg, 유입 1 kg/s, 유출 0.5 kg/s, 창 10 s | 미설명 손실 1−0.5−0.3=0.2 kg/s |
| 보일러 | 위와 같은 총재고 및 입출 유량 | 미설명 손실 0.2 kg/s |
| 열교환기 | 양측 유량 2 kg/s, cp=4180 J/(kg·K), 고온 360→340 K, 저온 290→310 K | Q=167200 W, 양단 접근 50 K, UA=3344 W/K |
| 필터·배관 | 차압 400 Pa, 유량 0.02 m3/s, 기준 0.01 m3/s, 지수 2 | 400×(0.01/0.02)²=100 Pa |
| 기화기 | 유량 2 kg/s, 입출구 엔탈피 100/500 J/kg, 동일 기준 | 전달열량 2×(500−100)=800 W |
| RO | 유량 1e-4 m3/s, NDP=1e6 Pa, TCF=1, 면적 10 m2 | 투수성 1e-11 m/(Pa·s) |
| 밸브 | 명령 0.5, 위치 0.6, 순수 지연 0 | 추종 오차 0.1 |
| 탑 | 차압 400 Pa, 증기 유량 2 kg/s, 기준 1 kg/s, 증기지수 2·액체지수 0 | 기준 차압 100 Pa |
| 스팀트랩 | 증기 400 K, 트랩 340 K, 음향 0.1, 조용함 기준 0.2, 저온 한계 40 K | 저온·저음향 점수 (400−340)/40=1.5 |
| 냉동기 | 냉수 2 kg/s, cp=4180, 285→280 K, 전력 20000 W | Qe=41800 W, COP=2.09 |

손계산 비교의 최대 절대오차는 RO 1.62e-27 m/(Pa·s), 밸브 2.78e-17,
그 외 선택한 지표는 해당 입력에서 0이었습니다. 이 수치는 선택한 단순 문제의 오차이며
일반 입력의 오차 상한이나 센서 불확도가 아닙니다.

## 보완 전 실패와 수정

동일한 신규 시험 82개를 먼저 실행했을 때 6개가 실패했습니다. 수정 후 6개 모두
통과했습니다. 최초 실패 원문은 `outputs/staged_verification/before_fixes.xml`,
수정 전 소스 해시는 `before_source.json`에 보존했습니다.

| 실패 사례 | 수정 전 관찰 | 보완 후 기대·확인 결과 |
|---|---|---|
| 공백 단위 | 단위가 `" "`이어도 SensorBatch 생성 허용 | 공백만 있는 단위도 ValueError |
| 필터·배관 양수→0 | 최소 양수 차압에 유량 보정 0.25를 곱한 결과가 0이 되어 유효·정상 처리 | 측정 차압이 양수인데 계산값이 0이면 파생 지표를 무효 처리, UNKNOWN |
| RO 양수→0 | 작은 양수 유량×작은 TCF가 0으로 소실되어 투수성 저하 경보 | 연산 소실이면 UNKNOWN. **실측 유량 0**은 기존처럼 투수성 0으로 계산 |
| 탑 양수→0 | 작은 양수 차압의 보정 결과가 0이 되어 유효·정상 처리 | 연산 소실이면 UNKNOWN |
| 냉동기 양수→0 | 유효한 작은 열부하를 큰 전력으로 나누어 COP가 0으로 소실되어 성능 저하 경보 | 양의 열부하 조건에서 COP 소실은 UNKNOWN |
| 시계 해상도 부족 | t≈1e16 s에서 창 0.1 s가 부동소수점 뺄셈에서 사라져 창 계산을 유효 처리 | `inventory_window_below_clock_resolution` 사유로 UNKNOWN |

부동소수점 범위에서 계산값이 나타낼 수 없거나 중간 연산에서 정밀도를 잃으면 판단을
보류합니다. 임의 정밀도 산술·로그 영역 전체 연산·자동 단위 스케일 변환을 새로 구현한
것은 아닙니다. 회귀 단계에서 RO 실측 유량 0, 차압 실측 0의 기존 처리도 재확인했습니다.

## 전체 실행 조건

각 조건은 별도 임시 디렉터리에서 기준을 학습한 뒤, 새 프로세스로 진단을 실행합니다.

- 정상: 정상 CSV 120표본, 10종 모두 경보 없음.
- 이상: 별도 운전 CSV 120표본, t=900 s 이후 10종에 이상 주입. 주입 전 경보 없음,
  이후 10종 모두 이상 의심 결과. 이는 독립적으로 조합한 합성 신호입니다.
- 전체 결측: 정상 기준은 유지하고 모든 선택 센서 값을 빈값으로 변경. 전 표본 UNKNOWN,
  10종 모두 데이터 부족으로 보고하며 경보 없음.
- 단위 오류: 재고 단위를 kg 대신 g로 선언. 종료코드 2, 최종 보고서 생성 안 됨.

## 실행과 근거 파일

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,physics]"
.\.venv\Scripts\python.exe scripts/verify_stages.py
```

모듈 연결 단계의 외부 시험에는 `.upstream`의 process-monitoring-toolkit, h2physics,
pipeline-safety-toolkit 체크아웃과 각 의존성이 필요합니다. 다른 위치는
`EQUIPMENT_UPSTREAM_ROOT`로 지정합니다. 누락으로 생략한 시험은 통과가 아닙니다.

검증 실행기: `scripts/verify_stages.py`. 신규 시험: `tests/test_six_stages.py`.
검증 보고서: `outputs/staged_verification/report.html`. 구조화 결과: 같은 폴더의
`results.json`. 단계별 JUnit XML·실행 로그·사용 명령, Python/의존성 버전, 실제 외부
저장소 커밋, 검증 대상 소스 해시를 함께 기록했습니다.

이번 여섯 단계는 **소프트웨어 검증**입니다. 기존에 확인한 정상 밸브 관성의 오경보,
탑 습식 운전의 모델 부족, 스팀트랩 음향과 실제 고장 사이의 검증 부족은 그대로 남습니다.
현장 진단 정확도·검출한계·오경보율·독립 고장 사례 평가는 수행하지 않았습니다.

# 냉동기 운전조건 반영과 분리 평가 — v0.5.0

`chiller_performance`에 선택 모드 `reference_mode="conditioned"`를 추가했습니다.
기존 단일 기준 방식은 `reference_mode="constant"`이며 기본값으로 유지합니다. 기존 입력과
정상 기준의 호환성을 보존하면서, 새 모드는 냉각수 입구온도 `cooling_in`(K)을 추가로
받아 부하·운전조건별 정상 성능을 계산합니다.

## 유지한 데이터 분리

| 용도 | 사용 데이터 | 수행한 작업 |
|---|---|---|
| 정상 학습 | `normal.xls` | 정상 회귀식·잔차 분포 학습. 이 파일 안에서만 모델 후보 선택 |
| 정상 보정 | `normal1.xls` | 원시 잔차 점수의 99백분위수로 경보 한계 결정 |
| 평가 | 기존 정상 12파일·고장 23파일 | 동결한 모델과 한계로 한 번의 비교 평가 |

원본은 [ASHRAE RP-1043 공개 재배포본](https://doi.org/10.6084/m9.figshare.28435232)이며,
단위 변환·물 밀도/cp·포화온도 계산·300 s 안정 운전 필터·중복 시각 처리·35개 평가 파일을
이전 평가와 동일하게 유지했습니다. 이전 고정 기준 방식의 TP/FP/TN/FN과 판단 표본 수가
기존 저장 결과와 **모두 일치하는지** 실행 중 확인합니다. 자료의 `COP`, `Active Fault`,
고장 파일명이나 라벨은 정상 모델 입력으로 사용하지 않았습니다.

학습·보정·평가 파일과 지문은 서로 다릅니다. 회귀계수, 후보 점수, 선택 모델, 보정 한계를
`frozen_development.json`으로 저장한 다음 평가 파일을 읽었습니다. 평가 중 재학습이나
임계값 조정은 하지 않았습니다.

**평가셋 재사용 한계:** 이 평가 파일은 이전 버전 평가에서 이미 사용한 자료입니다.
이번 비교에서 평가 데이터로 계수·모델·한계를 선택하지 않았지만, 새로운 블라인드
최종 검증셋이나 다른 냉동기에서의 일반화 시험은 아닙니다.

## 계산을 바꾼 내용

기존 방식은 정상 구간의 COP·증발기 접근온도·응축기 접근온도를 각각 중앙값 하나로
저장했습니다. 새 방식은 다음 조건으로 정상 상태의 기대값을 예측합니다.

```text
조건 x = [측정 냉각부하 Qe, 냉수 출구온도, 냉각수 입구온도]
Qe = 냉수 질량유량 × cp × (냉수 입구온도 − 출구온도)

예측 대상 y = [log(전력), 증발기 접근온도, 응축기 접근온도, log(냉수 유량)]
```

부하·냉수 출구온도·냉각수 온도에 따른 정상 전력의 변화는
[EnergyPlus 냉동기 Engineering Reference](https://bigladdersoftware.com/epx/docs/25-2/engineering-reference/chillers.html)의
성능 곡선에 사용되는 변수와 같은 원리에 근거합니다. 여기서는 정상 실측 데이터의
정규화 회귀식을 구현했으며, EnergyPlus 방정식 전체나 solver를 재현한 것은 아닙니다.

- 1차/2차와 ridge 강도 0.001/0.01/0.1/1의 8후보를 **정상 학습 파일 안에서만** 비교했습니다.
  연속된 안정 운전 구간 전체를 같은 fold에 두는 5분할 검증을 사용했습니다.
- 유효 학습 표본은 3,630개, 안정 운전 구간은 29개입니다. 선택 결과는 1차·ridge 0.001,
  정규화 교차검증 RMSE 약 0.291879입니다. 임의 행 섞기로 인접 표본을 나누지 않았습니다.
  이 구간들이 모두 다른 물리적 운전점이라는 뜻은 아닙니다.
- 전력은 정상 예측을 **초과한 방향**, 접근온도와 유량은 **양방향의 정상 모델 편차**를
  감시합니다. 잔차 규모는 학습 잔차의 robust MAD와 최소 규모 중 큰 값입니다.
  최소 규모는 로그 전력/유량에서 log(1.02), 접근온도에서 0.2 K로 사전 고정했습니다.
- 접근온도의 정상 예측값만 0 이상으로 제한합니다. 측정값·잔차는 잘라서 보정하지 않습니다.
- 유량은 정상 모델이 예측한 유량과 비교하는 진단 대상입니다. 기존처럼 정상 유량 범위를
  벗어났다는 이유만으로 모든 유량 감소 고장을 UNKNOWN으로 처리하지 않습니다.
- 냉각부하·냉수 출구온도·냉각수 입구온도의 학습 범위 제한과 물리 입력 검사는 유지합니다.
  온도 범위 여유는 관측 범위의 10% 또는 1 K 중 큰 값이며, 절대온도의 10%를 쓰지 않습니다.
- 전력·냉매 포화온도·판정 대상 유량을 정상 예측 조건에 그대로 넣어 고장 영향을 지우지
  않았습니다. 다만 Qe 자체는 유량과 온도에서 계산하므로 공통 센서 오차의 영향은 남습니다.

보정 전의 점수 1은 잔차 규모 하나에 해당하며 경보용으로 충분하지 않습니다. 독립 정상
보정의 99백분위수는 새 방식에서 약 **5.98505**, 이전 방식에서 약 **1.79507**였습니다.
새 `calibrate()`는 이를 기준 파일에 저장하고, `score()`는 원시 잔차 점수를 그 한계로
나눈 값을 반환합니다. 따라서 기존 결과·경보 계약의 `score > 1`과 지속시간 규칙을
그대로 사용합니다. 점수는 고장 확률이나 보장된 오경보 확률이 아닙니다.

## Python 사용

```python
from equipment_diagnostics import ChillerPerformanceDiagnostic

channels = {
    "chilled_in": "tei", "chilled_out": "teo",
    "cooling_in": "tci", "cooling_out": "tco",
    "evaporating_temperature": "evap", "condensing_temperature": "cond",
    "chilled_flow": "flow", "electric_power": "power",
}
# 아래 차수·ridge는 이번 정상 학습 파일의 내부 검증에서 선택한 값입니다.
model = ChillerPerformanceDiagnostic(
    channels, reference_mode="conditioned",
    regression_degree=1, ridge_alpha=0.001, persistence_s=30,
)
model.fit(normal_training_batch)
model.calibrate(separate_normal_calibration_batch, quantile=0.99)
result = model.score(evaluation_batch)
```

온도는 K, 유량은 kg/s, 전력은 W입니다. 정상 지위는 호출자가 확인해야 합니다.
동일 학습 배치를 보정에 재사용하면 거부하지만, 파일 지문이 다르다는 검사만으로
통계적 독립성이 증명되지는 않습니다. 호출자가 파일·날짜 분리를 유지해야 합니다.

`model.reference`에는 회귀식·학습 범위·정상 보정 한계와 지문이 함께 저장됩니다.
동일 설정의 `set_reference()`로 복원할 수 있고 분할 처리와 기존 어댑터에서 사용합니다.
정상 보정 후에는 `score_semantics="ratio_to_normal_calibrated_threshold"`를 결과와
`process-monitoring-toolkit` 연결에 보존합니다. 저장 기준을 바꾸면 활성 스트림은
명시적으로 reset해야 합니다. `score()` 중 온라인 재학습은 하지 않습니다.

## 재현과 검증

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,physics,public-data]"
# 원본 자료가 없으면 먼저 이전 공개 자료 평가의 다운로드를 실행
.\.venv\Scripts\python.exe scripts/validate_chiller_upgrade.py
.\.venv\Scripts\python.exe scripts/audit_chiller_upgrade.py
```

`outputs/chiller_upgrade/report.html`은 네 설정·공통 표본·고장별 비교표입니다.
`results.json`에는 파일별 혼동행렬·UNKNOWN 사유·기존 결과 재현 확인·소스 및 자료 해시가
있습니다. `frozen_development.json`은 평가 전에 저장한 학습/보정 기록이고,
`predictions.csv`는 같은 원본 시각에 개선 전후 판단을 나란히 저장한 표본별 결과입니다.
별도 집계 코드 `audit_chiller_upgrade.py`는 CSV에서 네 설정의 혼동행렬과 공통 표본을
다시 세고, 분리 파일·동결 기록·평가 소스 해시를 대조합니다.

새 모드의 학습·고장 주입, 물리/학습 범위 밖 입력, JSON 저장·복원, 실패한 재학습과
보정, 보정 데이터 분리, 분할 처리·인과성, 보정 후 점수 의미를 시험했습니다. 기존
기능·물리·전체 실행을 포함한 167개와 실제 외부 저장소 연결 7개가 통과했습니다.

전체 검출률은 여전히 34.56%이며, 오일 과다·약한 오염 등은 미해결입니다. 다른 설비나
새 운전전략에서는 정상 모델과 적용범위를 다시 검증해야 합니다. 이번 비교를 신규
냉동기의 현장 성능 보증이나 독립 블라인드 최종 검증으로 해석하지 않습니다.

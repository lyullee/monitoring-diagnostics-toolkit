# 필터 오경보·히트펌프 EF 검출 개선 (v0.10.0)

2026-11-05. 학습·보정·평가를 분리했고, 기존 Test 재사용 결과와 이전에
사용하지 않은 원본 관측 결과를 구분했다. 첫 성공 평가 후 설정을 다시 조정하지 않았다.
미사용 후반 결과가 좋지 않은 부분도 그대로 남겼다. 시뮬레이션 수치를 합산하지 않았다.

## 새로 사용한 관측과 새 독립 데이터의 차이

[HSE 필터 배포 v8](https://www.kaggle.com/datasets/prognosticshse/preventive-to-predicitve-maintenance)
의 기존 미사용 `Train_Data_Uncensored.mat`를 읽었다. 50시험 전체의 초기 관측이
기존 CSV와 최대 오차 1e-9 이내로 일치함을 검사했다. 실제 최대 오차는
약 5.7e-14다. MATLAB MCOS 구조를 원본 그대로 읽고, 모든 시험에서 처음 600Pa를
초과한 관측이 마지막 행임을 확인했다. 이는 **미래 교체 기준 정답**이며 현재 막힘
시작의 독립 정답이 아니다. 28번 시험은 기존 검열 이후 원시 시간이 역전되어 전체 제외했다.
시간을 임의로 이어 붙이지 않았다.

새 모형의 시험체 분리: ID %5가 1/2/3이면 학습(28 제외, 29시험), 4이면 보정
(10시험), 0이면 미사용 후반 평가(10시험)다. 동일 시험체의 행을 학습·보정·평가에
나누어 넣지 않았다. 기존 Test 50시험은 학습·보정에 사용하지 않고 재사용 평가만 했다.

| 이전 미사용 관측: 기존 Train 10시험의 검열 뒤 3,206행 | 정확도 | 검출률 | 오경보율 | 판단률 |
|---|---:|---:|---:|---:|
| 기존 저항 기준 | 75.14% | 100.00% | 100.00% | 100% |
| 새 수명 모형 | 88.02% | 96.68% | 38.14% | 100% |

새 모형 TP/FN/FP/TN=2,329/80/304/493, 기존=2,409/0/797/0이다.
수명 말기 후반 자료이므로 기존 Test와 분포가 다르고, 위 표끼리 수치를 직접 순위
비교하면 안 된다. 평가 대상 3,206행은 모두 판단했으며, 해당 10시험의 전체 원시
행 대비 판단률 31.87%는 앞부분을 후반 평가에서 제외한 결과다.

이 후반 관측은 이전 점수 계산·보정에서 사용하지 않았으나 **기존 시험체의 새 관측**이다.
새 모형에서는 시험체까지 분리했지만, 기존 저항 기준은 과거에 해당 시험체의 초기
보정 구간을 본 이력이 있다. 새 설비나 새 독립 자료원에서의 전이 성능으로 부르지 않는다.
후반 오경보율 38.14%가 남아 현장 채택을 확정하지 않는다.

## 구현

`FilterServiceRiskModel`은 과거 10초 창에서 log(1+차압)의 기울기를 계산한다.
차압·유량비의 로그와 압력 제곱·교호항으로 log(남은 교체 수명)을 ridge=0.01로
회귀한다. 수명 정답은 관측 시각부터 처음 DP>600Pa까지 시간이다. 평가 RUL은
특징·학습·보정에 들어가지 않는다. 절대 유량 단위는 가정하지 않고 학습 시험의
유량 중앙값으로 나눈 비를 쓴다. 시간 창은 관측 현재에서 끝나며 미래 행을 보지 않는다.
끊김·결측·시험 경계에서 이력을 초기화한다.

별도 보정 10시험의 RUL>30초 표본 점수 95백분위수를 한계로 고정하고 1초 지속
경보를 적용했다. 이 95백분위수는 평가 오경보 5%를 보장하는 값이 아니다.
훈련과 달리 평가 후반의 음성 표본은 교체 시점에 가까워 오경보가 더 높다.
목표 시간은 이전과 같은 30초로 유지했다. 새로운 수명 API는 정답을 받는 지도학습이므로
정상 기준 학습 전용 CLI 목록 11종과 별도로 Python에서 제공한다.

`HeatPumpPerformanceDiagnostic(feature_set="extended")`는 기존 네 잔차에
증발·응축 온도, 전력·압축기 속도·난방 COP의 로그 잔차를 추가한다. 압축기 속도는
고장 때문에도 변할 수 있으므로 설명변수가 아닌 **감시 출력**으로 사용한다.
기존처럼 명목 부하만으로 정상 기대값을 학습한다. Carnot 비율이 증발온도 하락의
영향을 일부 상쇄하더라도 절대 증발온도 잔차를 따로 감시할 수 있다.
실측 물 유량이나 원수 온도는 원본에 없으므로 만들어 넣지 않았다.

정상 보정 자료의 채널별 99백분위수(하한 1)로 각 잔차를 정규화한 뒤 최대값의
99백분위수로 전체 한계를 정했다. 이는 같은 보정 자료를 쓰는 한 번의 보정 절차이며
독립적인 두 보정 시험이 아니다. 한 채널의 큰 정상 변동이 모든 채널의 한계를
끌어올리는 문제를 줄인다. 기존 네 채널 설정은 기본값으로 유지했다.
기존 정상 시간 분할, 중간 제외 구간, 시동 180초 제외, 30초 지속조건을 유지했다.
기존 고장 정답은 최종 집계에서만 사용했다. 모델 구조 선택 자체는 기존 실패 결과를
본 개발이므로 동일 Test에서의 결과는 모두 재사용 평가다.

```python
from equipment_diagnostics import FilterServiceRiskModel, HeatPumpPerformanceDiagnostic

# batch에는 차압 Pa와 무차원 유량비만 넣고 정답은 별도 배열로 전달한다.
risk = FilterServiceRiskModel(
    {"pressure_drop": "dp", "flow_ratio": "flow_ratio"}, persistence_s=1)
risk.fit(train_batch, train_remaining_life_s)
risk.calibrate(calibration_batch, calibration_remaining_life_s, negative_quantile=.95)
result = risk.score(evaluation_batch)

# hp_channels는 기존 역할→채널 매핑이다. 학습과 보정은 서로 다른 정상 자료다.
hp = HeatPumpPerformanceDiagnostic(hp_channels, reference_mode="load_conditioned",
                                  feature_set="extended", persistence_s=30)
hp.fit(normal_training).calibrate(normal_calibration, quantile=.99)
```

## 새 독립 히트펌프 EF 검증: 미완료

[기존 TRI-HP 원본](https://zenodo.org/records/5155136)은 단일 프로토타입의
기존 모든 고장 시트를 이미 평가해 새 홀드아웃 시험이 없다.
[NIST 공개 FDD 자료](https://www.nist.gov/el/beed/hvacr-equipment-performance-group/fault-detection-and-diagnosis-research-data)
도 확인했지만 Appendix D 원본 다운로드는 HTTP403으로 확보하지 못했다. 또한 냉방
공기 유량 감소는 이번 난방 물 유량 감소와 운전 모드·입력이 달라 직접 같은 기준으로
평가할 수 없다. 이는 해당 자료 전체가 영구 접근 불가라는 뜻은 아니다.
[다른 R290 열역학 자료](https://zenodo.org/records/22097811)는 충전량 변화 시험으로
EF 정답을 제공하지 않는다. 이를 EF 양성/정상 정답으로 바꾸지 않았다.
따라서 새 독립 EF 정확도·검출률·오경보율은 null로 기록했다.

TRI-HP의 [실험 검증 보고서](https://www.tri-hp.eu/fileadmin/downloads/Deliverables/D6.3_-_Validation_of_the_self-diagnosis_efficiency.pdf)
도 고장과 부하 모두에서 변하는 압축기 속도를 구동 변수로 쓰는 어려움과
증발기 유량 감소의 작은 COP 영향을 보고한다. 이번 구현은 그 알고리즘의 재현이 아니다.

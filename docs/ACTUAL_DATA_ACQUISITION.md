## 1. 필터: 가장 먼저 적용 검토할 자료

[HSE 제작자 저장소](https://www.kaggle.com/datasets/prognosticshse/preventive-to-predicitve-maintenance)의 **버전 8**을 받았습니다.
실제 저장소 주소는 `predicitve`라는 오타를 포함합니다. 또한 다운로드에 버전을 명시해야 정상 응답을 받았습니다.
제3자 가공 자료나 합성 RUL을 가져오지 않고 제작자의 ZIP과 PDF 설명서를 보관했습니다.

CSV 열은 `Data_No`, `Differential_pressure`, `Flow_rate`, `Time`, `Dust_feed`, `Dust`이며 Test에는 `RUL`이 추가됩니다.
총 78,834행이고 결측값은 없지만 초기 `Flow_rate=0` 표본은 존재합니다. 이 표본을 몰래 제거하거나 보간하지 않았습니다.
Train/Test 안의 시험 ID가 각각 1부터 시작하므로 `(source_split, Data_No)`로 구별해야 합니다.
같은 ID의 Train/Test 측정 접두 구간이 완전히 동일한 경우는 0개였으나, 이 비교만으로 모든 물리적 독립성을 증명하지는 않습니다.

제작자 설명상 자료는 우측 검열을 포함하며 실패는 차압 600 Pa 초과로 정의합니다.
따라서 600 Pa를 정답으로 만들고 같은 차압 기준으로 감지해 얻은 높은 정확도를 독립적인 막힘 진단 성능이라고 주장하면 안 됩니다.
RUL은 평가용 목표값이며 입력 특징이나 보정 임계값 선택에 사용하지 않습니다.
`Train_Data_Uncensored.mat`도 원본에 있으나 숨겨진 시험 목표 복원이나 학습·평가 혼합에 사용하지 않았습니다.

차압 Pa·시간 초는 원문에서 확인했습니다. **Flow_rate 절대단위는 배포 설명에서 명확히 확정하지 못했으므로 SI 변환을 하지 않았습니다.**
제3자 설명에는 분진 공급량의 단위까지 원문과 다르게 적힌 사례가 있어 그대로 따르지 않았습니다.
원본 설명에서 분진 공급량 `Dust_feed`는 mm3/s이며 차압 센서 범위는 0~2500 Pa입니다.
유량 센서 값은 제작자가 분진 공급 영향에 대해 보상한 실측값입니다. 미보정 ADC 원신호라고 부르지 않습니다.

## 2. RO: 실제 자료는 확보, 고장 정답은 별개

[NREL/OpenEI 실험 자료](https://mhkdr.openei.org/submissions/649)에서 아래 파일을 확보했습니다.

- `steady_state.zip`: CSV 1개
- `ramp.zip`: CSV 4개
- `sine.zip`: CSV 23개
- `README.rtf`: 센서·실험 조건·단위·막 사양 설명

막은 DuPont FilmTec SW30-4040, 문서의 유효 면적은 7.4 m2, 수집 간격은 0.25초입니다.
압력 psi, 유량 L/min, 온도 °C, 전도도 mS/cm 또는 uS/cm 등 원래 단위를 유지했습니다.
`Water Flux`는 투과수 유량과 막 면적에서 계산한 값으로 별도의 독립 유량 센서가 아닙니다.
급수는 탈염소 수돗물과 NaCl로 만들었고, 문서에는 전도도–농도 관계가 제공됩니다.
실제 삼투압 계산에 사용할 활동도/물성 모델의 적합성은 별도로 확인해야 합니다.

압력 파형을 바꾼 **실제 막 실험**이며, 압력 변화 자체를 막 오염 고장으로 라벨링하지 않습니다.
정상 보정과 동적 응답 검증에는 유용하지만, 이 자료만으로 막 오염 검출률·오경보율을 산출할 수는 없습니다.
WEC-Sim 생성 파형을 사용한 별도 파일은 이번 확보량에 포함하지 않았습니다.

## 3. 열교환기: 실제 습식 코일 자료

[제작자 Mendeley 자료](https://data.mendeley.com/datasets/s6d23g2m2w/1)의 XLSX를 받았고 **게시자 SHA256과 일치**했습니다.
시트는 Baseline/RH85/V1/V2/F1/F2/F3/F4입니다. 다른 습도·유속·오염 조건이며 8개의 독립 반복 실험으로 과장하지 않습니다.

- `m_w`는 착상 형성률이고 `m_t`는 누적 착상량입니다. 브라인 질량유량이나 탱크 재고로 잘못 매핑하지 않습니다.
- Time의 단위 행은 min이지만 실제 Excel 값은 시각 객체입니다. 그대로 경과시간 숫자로 취급하지 않습니다.
- `RH_1`의 단위 행에 온도 단위가 적혀 있어 의미와 불일치합니다. 원본을 임의 수정하지 않고 기록했습니다.
- 공기 응축·착상의 잠열이 있어 현재 단상·일정 cp UA 계산의 정확도 검증에 그대로 쓰지 않습니다.

## 4. 탱크: 실제 누설 기록 확보와 한계

[논문 제작자 GitHub](https://github.com/iraptis/Liquid-Level-Control-System-Fault-Diagnosis-Data)를 다음 커밋에 고정해 받았습니다.

`57557ea940bdc379fc0a5052a04c91ce1c9f86cd`

저장소의 DataSet1 안에는 접두사 없는 기록과 `2_`, `3_` 기록이 있습니다.
25개 센서 파일을 확보했고 센서 파일 전체의 데이터 행 합은 5,153개입니다. 이는 동기화한 5,153개의 독립 실험을 뜻하지 않습니다.
19개 Excel 파일은 Strict OOXML이므로 일반 Excel 파서가 시트를 인식하지 못했습니다.
원본을 고치지 않고 XML에서 셀 좌표·값·헤더를 직접 읽어 별도 CSV로 내보냈습니다.

[원 논문](https://onlinelibrary.wiley.com/doi/full/10.1002/adc2.70011)은 유량계가 정확한 유량을 제공하지 못했다고 명시합니다.
대신 누설이 들어간 시점을 식별하는 용도로는 사용할 수 있다고 설명합니다.
따라서 우선 누설 시점·액위 모델의 검증 후보로 보관하며, 지금 바로 정량 질량수지의 높은 정확도를 보고하지 않습니다.
압력은 전압으로 기록되어 있으며 센서별 측정 시각과 시스템 시각이 구분돼 있어 교정·동기화 검토가 필요합니다.

## 5. 히트펌프: 다른 실제 기계의 고장 실험

[TRI-HP/IREC 제작자 Zenodo](https://zenodo.org/records/5155136)에서 XLSX를 받았고 **게시자 MD5와 일치**했습니다.
프로판 수–수 히트펌프의 난방 모드 실험으로, 냉각 모드 R134a RP1043 자료와 구분합니다.
NF10/NF12의 정상 두 조건과 EF/CVL/LL/OC의 고장·강도 정보를 포함합니다.
전력·응축기 열량·포화온도·과냉도·토출온도·냉매 유량·압축기 회전수·과열도를 제공합니다.

주 측정과 과열도는 **서로 다른 시각 열**로 같은 시트 옆에 배치되어 있습니다.
행 번호로 합치지 않도록 `*_main.csv`와 `*_superheat.csv`로 분리해 내보냈습니다. 보간이나 임의 시각 맞춤을 하지 않았습니다.
냉동기 모듈의 물측 입출구·유량 센서가 모두 있지는 않아 기존 모듈의 즉시 검증 자료로 선언하지 않았습니다.
보고된 COP에서 부족한 센서값을 역산해 정답을 재사용하지 않습니다. 고장 코드·강도는 라벨이며 모델 입력이 아닙니다.
